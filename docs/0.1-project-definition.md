# OpenSourceLens — Project Definition & Problem Statement

## 1. Problem Statement

Open-source software projects hosted on GitHub contain rich, publicly accessible historical data spanning commits, contributors, pull requests, issues, discussions, and releases. 

However, extracting meaningful intelligence from this data is challenging:
- **Raw Metric Superficiality:** GitHub provides raw counts (e.g. 5,000 commits, 120 contributors, 300 open issues), but fails to analyze what these numbers signify. Is commit activity accelerating or stagnating? Is project development driven by a broad community or concentrated in a fragile single-maintainer bottleneck? Are pull requests merging smoothly or stalling in prolonged code review backlogs?
- **Issue Triage & Categorization Overhead:** Incoming bug reports, feature requests, documentation questions, and help inquiries arrive continuously without standardized labeling. Maintainers spend significant manual effort categorizing and triaging issues.
- **Duplicate & Related Problem Proliferation:** Contributors frequently submit duplicate bug reports or overlapping proposals with different wording, fragmenting discussions and wasting developer hours.
- **Unpredictable Resolution Lifecycles:** Contributors and engineering teams lack insight into how long issues and pull requests typically take to resolve, or what characteristics (author relationship, complexity, code evidence) affect resolution velocity.

**OpenSourceLens** bridges the gap between raw GitHub data and actionable software engineering intelligence by applying rigorous Data Science, statistical analysis, machine learning, and natural language processing to **any eligible public GitHub repository**.

---

## 2. Product Identity: What OpenSourceLens Is

**OpenSourceLens** is a **Data Science-powered GitHub Repository Intelligence Platform**.

A user provides any eligible public GitHub repository URL (e.g., `https://github.com/fastapi/fastapi` or `pallets/flask`). The platform dynamically retrieves the repository's available historical data, runs it through an integrated data engineering and machine learning pipeline, and generates an interactive, multi-dimensional **Repository Intelligence Workspace**.

### Deriving Intelligence vs. Displaying Raw Information

OpenSourceLens does not merely reproduce existing GitHub interface numbers. It derives higher-order statistical and predictive intelligence:

| GitHub Raw Information | OpenSourceLens Derived Intelligence |
|---|---|
| Displays total commit count | Analyzes time-series development velocity, activity consistency, change points, and anomaly detection |
| Lists contributors | Evaluates contributor retention, cohort survival, contribution concentration (Gini coefficient & entropy), and community decentralization |
| Shows pull requests | Analyzes code review latency, time-to-first-review, merge duration distributions, and pull request review bottlenecks |
| Lists issues and labels | Performs NLP-based taxonomy classification, semantic duplicate retrieval via dense vector embeddings, and resolution-time distribution modeling |
| Lists release tags | Evaluates release cadence regularity, versioning consistency, and historical stability |

## 3. Product Scope: Dynamic Ingestion vs. Benchmark Datasets

### Universal Product Scope (Single-Repository Focus for v1)
The primary user experience is centered around dynamic, single-repository analysis:
1. **Repository Entry & Validation:** A user enters any public GitHub repository URL or slug (`owner/repo`). The platform validates repository existence, public accessibility, and activity thresholds.
2. **Dynamic Ingestion & Storage:** The backend queries the GitHub REST API, collects repository metadata, commit history, contributor participation, pull requests, and issues within an allocated rate-limit budget, and persists them into a relational schema.
3. **Data Science Processing:** The ingested data is normalized, feature-engineered, and processed through statistical analyzers and pre-trained machine learning models.
4. **Interactive Intelligence Workspace:** The user explores development activity, contributor dynamics, PR bottlenecks, issue taxonomy, and receives an automated evidence-backed intelligence report.

### Benchmark & Offline Evaluation Repositories
Four diverse open-source repositories were selected during initial development:
- `microsoft/vscode` (Developer Tools & IDE)
- `pytorch/pytorch` (Machine Learning & Deep Learning Framework)
- `kubernetes/kubernetes` (Cloud Native Infrastructure)
- `huggingface/transformers` (NLP & Generative AI Library)

**These four repositories serve as offline benchmark datasets, baseline calibration sources, and experimental validation testbeds.** They do **NOT** define the boundaries of the production system. All machine learning models, statistical heuristics, and frontend views must be engineered to generalize to arbitrary unseen repositories.

## 4. Target Users

OpenSourceLens is designed as a general-purpose repository intelligence platform for:

- **Open-Source Contributors:** Evaluating project health, responsiveness, review velocity, and good starting points before investing time.
- **Repository Maintainers & Engineering Leads:** Identifying triage bottlenecks, monitoring contributor retention, detecting backlog growth, and understanding PR review friction.
- **Software Engineering Researchers & Students:** Conducting empirical studies on open-source development dynamics, collaboration networks, and issue lifecycle distributions.
- **Engineering Teams & Evaluators:** Performing due diligence on open-source dependencies and assessing project longevity, maintenance activity, and community vitality.

## 5. Main & Supporting Objectives

### Main Objective
To develop an intelligent, general-purpose Data Science platform that dynamically analyzes public GitHub repositories and applies machine learning, statistical modeling, and natural language processing to generate actionable repository intelligence through an interactive web application.

### Supporting Objectives
1. **Dynamic Data Ingestion:** Build a robust API client capable of validating, harvesting, and budgeting data collection from any public GitHub repository.
2. **Data Engineering & Relational Persistence:** Clean, normalize, and store repository entities (metadata, commits, contributors, PRs, issues, labels) in an indexed database.
3. **Development Activity Modeling:** Implement time-series analysis to detect activity trends, development consistency, and anomalous lulls or spikes.
4. **Contributor Ecosystem Analytics:** Model contributor retention curves, calculate Gini coefficients of contribution inequality, and assess community bus-factor risks.
5. **Pull Request Lifecycle Analytics:** Model review latencies, calculate merge survival probabilities, and identify review bottlenecks.
6. **NLP Issue Classification:** Train and evaluate generalizable classifiers (classical ML baselines vs. fine-tuned transformer models) to categorize issues into functional taxonomies without requiring repository-specific target labels.
7. **Semantic Duplicate Retrieval:** Implement dense vector sentence embeddings to search and retrieve semantically similar issues across repositories in real time.
8. **Resolution Velocity Forecasting:** Provide empirical SLA percentiles and advisory velocity predictions grounded in observable creation-time characteristics.
9. **Interactive Web Workspace:** Present dynamic multi-domain intelligence and an automated repository findings summary through a modern, responsive user interface.

---

## 6. What OpenSourceLens Is Not

To maintain technical focus and research integrity, OpenSourceLens is explicitly **not**:
- A replacement for GitHub itself or a generic project management tool.
- A general-purpose conversational chatbot or generative code assistant.
- An automated code modification or automatic issue-closing bot.
- A static showcase restricted to four pre-selected repositories.
