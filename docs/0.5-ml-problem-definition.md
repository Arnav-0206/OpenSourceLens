# OpenSourceLens — Data Science & Machine Learning Problem Definitions

> [!NOTE]
> **Implementation Alignment Note:** While this document outlines the conceptual DS formulation, the implemented Phase A classifiers target 3 classes (`bug`, `feature`, `other`), and the implemented Phase C.2 anomaly/change-point detectors use rolling robust MAD (with z-score/Poisson fallbacks) and `max_ssb_permutation_test` rather than fixed $|z_t| > 2.5$. See [docs/analytics.md](./analytics.md) and [docs/architecture.md](./architecture.md#6-phase-a-pre-trained-machine-learning-services).

OpenSourceLens formulates six distinct Data Science, statistical modeling, and machine learning problems across the repository lifecycle.

---

## Problem 1: Generalizable Issue Classification (Supervised NLP)

### 1.1 Objective
Automatically classify incoming GitHub issues into functional categories (`bug`, `feature`, `documentation`, `question`, `other`) using natural language processing.

### 1.2 Input & Output
- **Input:** Issue `title` and optional `body` description.
- **Output:** Predicted canonical category $\hat{y} \in \{\text{bug}, \text{feature}, \text{documentation}, \text{question}, \text{other}\}$ and a calibrated probability distribution $\mathbf{p} = [p_1, \dots, p_5]$ where $\sum p_i = 1.0$.

### 1.3 Modeling Architecture
- **Classical ML Baseline:** Sublinear TF-IDF vectorizer (10,000 features, unigrams and bigrams) paired with:
  - Logistic Regression ($L_2$ penalty, $C=1.0$)
  - Linear Support Vector Machine (LinearSVC with calibrated softmax hyperplanes)
- **Champion Deep Learning Model:** Fine-tuned `distilbert-base-uncased` transformer (6 layers, 12 attention heads, 66.9M parameters). Evaluated on benchmark holdout data at **81.3% test accuracy** and **0.584 macro F1**.
- **Generalization Protocol:** Models are trained on pooled benchmark datasets using structural subword vocabularies to ensure zero-shot classification on unseen repositories.

## Problem 2: Dynamic Semantic Duplicate & Related Issue Retrieval

### 2.1 Objective
Identify existing GitHub issues that discuss identical defects or related feature proposals, preventing duplicate discussion fragmentation.

### 2.2 Input & Output
- **Input:** Query issue text (title and description) and a target repository context.
- **Output:** Ranked list of top-K candidate issues with metadata and cosine similarity scores $S_c \in [-1.0, 1.0]$.

### 2.3 Retrieval Architecture
1. Text is sanitized and passed to Sentence-Transformers `all-MiniLM-L6-v2`.
2. Model produces an L2-normalized 384-dimensional dense semantic embedding vector $\mathbf{v}_q$.
3. Cosine similarity is computed against all candidate vectors in the repository:
   $$\text{Similarity}(\mathbf{v}_q, \mathbf{v}_i) = \mathbf{v}_q \cdot \mathbf{v}_i$$
4. Candidates are ranked descending by similarity score, filtered by a configurable threshold (default $\tau \ge 0.50$).

## Problem 3: Development Activity Time-Series & Anomaly Detection

### 3.1 Objective
Quantify development momentum, identify sprint cadences, and detect anomalous disruptions in project activity.

### 3.2 Methodology
- **Time-Series Aggregation:** Commit counts aggregated into weekly intervals $C_t = \{c_1, c_2, \dots, c_T\}$.
- **Trend Decomposition:** 4-week and 12-week moving averages to isolate directional momentum from high-frequency noise.
- **Statistical Anomaly Detection:** Rolling $z$-score evaluation identifying significant change points:
  $$z_t = \frac{C_t - \mu_w}{\sigma_w}$$
  Weeks where $|z_t| > 2.5$ are flagged as anomalous development bursts (e.g. major release preparation) or developmental lulls (e.g. holiday freezes, maintainer turnover).

## Problem 4: Contributor Ecosystem & Concentration Modeling

### 4.1 Objective
Measure community decentralization, contributor retention, and project sustainability ("bus factor" risk).

### 4.2 Methodology
- **Gini Coefficient of Contribution Inequality:**
  Computes the Lorenz distribution of commits across all contributors $N$:
  $$G = \frac{\sum_{i=1}^N \sum_{j=1}^N |x_i - x_j|}{2 N^2 \bar{x}}$$
  - $G < 0.60$: Decentralized community with healthy distributed ownership.
  - $G \ge 0.85$: High concentration / bus-factor vulnerability (heavy reliance on 1–2 individuals).
- **Contributor Retention (Cohort Survival):**
  Uses Kaplan-Meier survival curves to estimate the probability that a contributor who submitted a first PR/commit will return to contribute again after 30, 90, and 180 days.

## Problem 5: Pull Request Lifecycle & Review Bottleneck Detection

### 5.1 Objective
Diagnose maintainer review responsiveness, merge efficiency, and review pipeline bottlenecks.

### 5.2 Methodology
- **Non-Parametric Duration Metrics:** Time-to-first-response (TTFR) and Time-to-Merge (TTM) characterized using medians ($P50$) and interquartile ranges ($P25$–$P75$) to handle extreme right-skewness.
- **Review Starvation Detection:** Classifies open PRs into health states:
  - *Responsive:* Under active review within $\le P50$ days.
  - *Delayed:* Awaiting maintainer review $> P75$ days.
  - *Protracted:* High review comment count with stalled merge decisions.

## Problem 6: Issue Resolution Velocity Advisory

### 6.1 Objective
Forecast the expected turnaround velocity tier of an issue based solely on observable creation-time characteristics ($t=0$).

### 6.2 Methodology
- **Target Variable:** 4 operational speed brackets:
  - `< 1 Day` (Rapid resolution)
  - `1-7 Days` (Sprint turnaround)
  - `7-30 Days` (Moderate backlog)
  - `30+ Days` (Long-tail issue)
- **Feature Pipeline (Decoupled from Fixed Repositories):**
  - Text length (title and body word count, body-to-title ratio)
  - Code evidence (presence of code snippets, stack traces, URLs)
  - Author relationship (MEMBER vs. CONTRIBUTOR vs. external)
  - Creation context (day of week, hour of filing)
  - Initial label count
- **Model:** 100-tree Random Forest classifier achieving **88.11% adjacent accuracy ($\pm 1$ tier)**, providing actionable advisory guidance with conservative lower and upper confidence bounds.
