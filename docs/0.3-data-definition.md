# OpenSourceLens — Data Definition & Schemas

> [!NOTE]
> **Historical Data Planning Draft:** Field names in Section 2 (`committed_at`, `first_contribution_at`, `contributor_tier`, etc.) reflect an early planning draft. For exact implemented ORM column names and constraints, see [docs/database.md](./database.md).

## 1. Data Sources & Harvesting Principles

OpenSourceLens relies on the **GitHub REST API v3** to collect publicly accessible repository entities. 

To maintain reliable on-demand execution for arbitrary repositories while respecting GitHub API rate limits (5,000 requests/hour authenticated), the platform implements a **tiered data collection budget**:
- **Metadata Tier:** Instant single-call inspection of repository status, primary language, star counts, fork counts, and open issue counts.
- **Activity Tier (Sampled/Windowed):** Most recent 300 commits and 12-month aggregated commit activity statistics.
- **Contributor Tier:** Top contributors list and recent committer activity logs.
- **Pull Request Tier:** Most recent 150–300 pull requests (both merged and closed).
- **Issue Tier:** Most recent 300–600 issues (balanced between open and closed).
- **Releases Tier:** Official release tags and publication timestamps.

## 2. Entity Schemas

### 2.1 Repository Metadata
Basic metadata identifying the repository and its ecosystem:
- `id` (bigint, primary key): GitHub repository numeric ID.
- `repo_name` (varchar, unique): Canonical slug (`owner/repo`).
- `owner` (varchar): User or organization name.
- `name` (varchar): Repository name.
- `description` (text): Project description.
- `primary_language` (varchar): Dominant programming language.
- `stars_count` (integer): Total stargazers.
- `forks_count` (integer): Total network forks.
- `open_issues_count` (integer): GitHub reported open issue/PR count.
- `github_created_at` (timestamp): Initial repository creation on GitHub.
- `github_updated_at` (timestamp): Most recent push or activity timestamp.
- `collected_at` (timestamp): Local ingestion snapshot timestamp.

### 2.2 Development Activity & Commits
Tracks code modification frequency, timestamps, and commit patterns:
- `sha` (varchar, primary key): Git commit hash.
- `repository_id` (bigint, foreign key): Linked repository.
- `author_login` (varchar): Committer GitHub username.
- `committed_at` (timestamp): Commit timestamp (UTC).
- `day_of_week` (integer, 0–6): Temporal filing day.
- `hour_of_day` (integer, 0–23): Temporal filing hour.
- `message_length` (integer): Commit message character count.
- `is_merge_commit` (boolean): Whether commit represents a branch merge.

### 2.3 Contributor Ecosystem Entities
Tracks contributor participation, frequency, and tenure:
- `contributor_id` (bigint, primary key): Unique contributor record ID.
- `repository_id` (bigint, foreign key): Linked repository.
- `author_login` (varchar): GitHub username.
- `total_commits` (integer): Lifetime or windowed commit count.
- `first_contribution_at` (timestamp): Date of earliest recorded contribution.
- `latest_contribution_at` (timestamp): Date of most recent recorded contribution.
- `contributor_tier` (varchar): Categorization (`core`, `regular`, `casual`, `newcomer`).
- `retention_status` (varchar): Cohort survival state (`active`, `lapsed`, `one-time`).

### 2.4 Pull Request Entities
Captures code review pipelines, merge durations, and maintainer responsiveness:
- `id` (bigint, primary key): GitHub pull request ID.
- `repository_id` (bigint, foreign key): Linked repository.
- `pr_number` (integer): Repo-scoped PR number.
- `title` (text): Pull request title.
- `author` (varchar): Submitter GitHub username.
- `state` (varchar): `open`, `closed`, or `merged`.
- `created_at` (timestamp): PR opening timestamp.
- `closed_at` (timestamp, nullable): PR closure timestamp.
- `merged_at` (timestamp, nullable): PR merge timestamp.
- `time_to_merge_hours` (float, nullable): Derived continuous merge duration.
- `review_comments_count` (integer): Number of inline code review comments.
- `is_merged` (boolean): Whether the PR was accepted into the codebase.

### 2.5 Issue Entities
The primary textual and triage data asset:
- `id` (bigint, primary key): GitHub issue numeric ID.
- `repository_id` (bigint, foreign key): Linked repository.
- `repo_name` (varchar): Denormalized repository slug.
- `issue_number` (integer): Repo-scoped issue number.
- `title` (text): Raw issue title.
- `body` (text, nullable): Raw issue body description.
- `clean_title` (text): Sanitized title (code, URLs, and punctuation normalized).
- `clean_body` (text, nullable): Sanitized description text.
- `combined_text` (text): Concatenated title and description for NLP models.
- `state` (varchar): `open` or `closed`.
- `state_reason` (varchar, nullable): `completed`, `not_planned`, `duplicate`.
- `author` (varchar): Issue creator username.
- `author_association` (varchar): `OWNER`, `MEMBER`, `CONTRIBUTOR`, `NONE`.
- `is_internal_author` (boolean): Flag for maintainers/members.
- `created_at` (timestamp): Creation timestamp.
- `closed_at` (timestamp, nullable): Resolution timestamp.
- `comments_count` (integer): Total discussion comments.
- `canonical_label` (varchar): Standardized category (`bug`, `feature`, `documentation`, `question`, `other`).
- `speed_tier` (varchar, nullable): Historical resolution bracket (`< 1 Day`, `1-7 Days`, `7-30 Days`, `30+ Days`).
- `resolution_time_hours` (float, nullable): Closed issues resolution duration ($t_{\text{closed}} - t_{\text{created}}$).

### 2.6 Releases & Milestones
- `id` (bigint, primary key): Release numeric ID.
- `repository_id` (bigint, foreign key): Linked repository.
- `tag_name` (varchar): Version string (e.g. `v1.2.0`).
- `published_at` (timestamp): Publication timestamp.
- `days_since_prior_release` (float, nullable): Time interval from previous version tag.

## 3. Data Processing & Pipeline Flow

The system processes ingested entities through a multi-stage data science pipeline:

```
GitHub REST API v3
       ↓
Raw Entity Payloads (Temporary in-memory / cache)
       ↓
Data Cleaning & Text Sanitization (Code stripping, markdown removal, timestamp parsing)
       ↓
Feature Engineering (Word counts, code flags, Gini concentration, durations)
       ↓
Relational Persistence (SQLAlchemy ORM → SQLite WAL / PostgreSQL)
       ↓
Analytics & ML Inference (Time-series, survival estimation, DistilBERT classification, vector embeddings)
       ↓
Presentation Layer (Next.js Dashboard Charts & Reports)
```
